# CustomPS — план оставшихся работ (ROADMAP)

> Срез: 20.10.2026, ветка `main` на `913b34525c6d76499818f36dda014dee66ed7c8d`. Составлен по CustomPC, CustomPC2 и текущему коду. **Не считать задачу завершённой только потому, что есть модель БД или страница.** Обновлять статусы после проверки. P0 — до эксплуатации с реальными клиентами, P1 — запуск MVP, P2 — развитие.

## P0 — безопасность данных, работоспособность, качество

- [ ] **P0-01. Безопасная миграция существующей БД.** Сверить `_prisma_migrations`, текущую схему и baseline; сделать резервную копию и проверить восстановление; подготовить неразрушающий план миграции и проверить на копии данных. **Запрещено выполнять `prisma migrate reset` на БД с ценными данными.** Не считать инструкцию для чистой dev-БД инструкцией для production.
- [ ] **P0-02. Верификация сборок и CI.** Проверить backend `npm ci`, `prisma validate`, `prisma generate`, `npm test`, `npm run build`; frontend `npm ci`, `npm run build`; исправить воспроизводимые сбои. Убедиться, что Actions зелёный в main.
- [ ] **P0-03. Сквозное тестирование.** Проверить публичный сценарий «выбор услуги/сборки/конфигуратора → заявка → согласование → заказ → частичная/полная оплата → завершение», в том числе заказ только на услугу. Проверить ошибки и повторную отправку.
- [ ] **P0-04. Финансовая достоверность Dashboard.** Код исправлен: при неизвестной прибыли API возвращает `null`, отдаёт счётчики заказов с неизвестной себестоимостью/прибылью, а админка показывает неполноту данных. Добавлены регрессионные тесты. Осталось выполнить backend-тесты и build, frontend build и ручную проверку интерфейса, дат, фильтров, сумм и статусов оплаты.
- [ ] **P0-05. Безопасность.** Проверить JWT/cookie, права ADMIN/MANAGER на каждом endpoint, ограничение попыток входа, CORS, DTO, отсутствие секретов и персональных данных в логах; аудит зависимостей и устранение критичных уязвимостей.
- [ ] **P0-06. Гигиена репозитория.** Проверить, зачем отслеживается `backend/tsconfig.build.tsbuildinfo`; исключить генерируемые и чувствительные файлы, если они не нужны; не публиковать реальные `.env` и ключи.
- [ ] **P0-07. Production readiness.** HTTPS, домен, конфигурация переменных, production Docker/хостинг, backup/restore, мониторинг ошибок и логирование, smoke-тест после деплоя.

## P1 — готовый коммерческий сайт

- [ ] **P1-01. Полное SEO (важное требование CustomPC2).** Основа уже в main: sitemap, robots, canonical, metadata, OG. Проверить метаданные **всех** публичных страниц, динамическую карту сайта, 404/редиректы, robots/noindex для admin, JSON-LD (LocalBusiness/Service/Product/Breadcrumb по смыслу), уникальные H1, alt, перелинковку, скорость/Core Web Vitals, корректный `NEXT_PUBLIC_SITE_URL`, индексацию и вебмастера. Не обещать позиции в поиске без измерений.
- [ ] **P1-02. Типовой договор и генерация документов (важное требование CustomPC2).** Найти и согласовать юридически подходящий шаблон для выбранной юрисдикции и вида работ; хранить версионируемый шаблон с переменными (например `{{customer_name}}`, `{{order_number}}`, `{{price}}`, `{{scope}}`, `{{deadline}}`, `{{warranty}}`); генерировать DOCX/PDF из заказа, проверять обязательные поля, сохранять версию/снимок, давать предварительный просмотр и скачивание. Не подменять юридическую проверку автоматической генерацией.
- [ ] **P1-03. Реальное наполнение.** Владелец самостоятельно добавляет портфолио и фотографии (как договорились в CustomPC2); разработка должна обеспечить удобный CRUD, порядок изображений, публикацию, валидацию и оптимизацию. Заполнить услуги, контакты, часы, ссылки, реальные сборки и отзывы.
- [ ] **P1-04. Уведомления.** Проверить реальную отправку email при новой заявке, логирование ошибок, безопасную конфигурацию Resend и защиту от повторных уведомлений; при необходимости шаблоны и уведомления об изменении статуса.
- [ ] **P1-05. Каталог и конфигуратор.** Проверить совместимость CPU/сокета, RAM, форм-фактора, питания, габаритов GPU/корпуса, охлаждения, наличия и цен; подготовить тест-кейсы на пограничные комбинации и объяснения причин несовместимости. Проверить, что рекомендация укладывается в бюджет и не выбирает отсутствующие товары.
- [ ] **P1-06. UX/UI и доступность.** Проверить мобильные экраны, формы, состояния загрузки/ошибок, контрастность, клавиатурную навигацию, Lighthouse и реальную скорость; убрать демонстрационные заглушки.
- [ ] **P1-07. CRM и отчётность.** Проверить согласованную стоимость, статусы и историю, частичные платежи, себестоимость услуг, корректный расчёт маржи, фильтры Dashboard и экспорт при реальной потребности.
- [ ] **P1-08. Документация и данные.** Обновить устаревший корневой README и `2BACKLOG.md` под актуальный main; подготовить инструкции для админа, безопасный seed без дубликатов, отдельные demo-данные только для dev (PR #61 не считать внедрённым без проверки main).

## P2 — развитие после запуска

- [ ] **P2-01. Блог/статьи.** Модель Article уже существует; создать и проверить редактор, публичные страницы, публикацию и SEO.
- [ ] **P2-02. Аналитика.** Настроить события отправки заявки, переходов из каталога и конфигуратора, конверсии; обеспечить соблюдение требований к согласию/приватности.
- [ ] **P2-03. Удобство оператора.** Поиск, сортировка, массовые операции, журнал изменений, расширенная статистика, шаблоны ответов.
- [ ] **P2-04. Расширение каталога.** Импорт/обновление цен и остатков только после определения источников и правил качества данных.
- [ ] **P2-05. Автоматизация тестирования.** Дополнить unit/integration тесты минимальным набором Playwright E2E для критического пути; затем расширять покрытие по рискам.

## Рекомендуемый порядок
1. Сначала P0-01–P0-07: нельзя рисковать существующей БД или принимать реальные заказы без надёжной работы.
2. Затем параллельно P1-01 (SEO) и P1-02 (договор), после этого наполнение и сквозная приёмка.
3. P2 — только после проверенного MVP.

## Критерии завершения
Для каждого пункта: код в отдельной ветке → тесты/сборка → ручная проверка сценария → PR → merge в main → обновление `IMPLEMENTED.md` и этого файла. **Статус «сделано» означает наличие проверенного результата, а не только открытого PR.**
