# CustomPS

Веб-сервис локальной продажи и сборки персональных компьютеров (Нефтекамск).

Проект объединяет каталог готовых ПК, конфигуратор, подбор комплектующих, приём заявок и административную панель. Backend построен на NestJS, frontend — на Next.js, данные хранятся в PostgreSQL через Prisma.

## Текущее состояние проекта

На текущем этапе реализовано и связано между собой основное MVP-ядро:

- каталог готовых сборок ПК;
- карточки готовых сборок и их состав;
- управление комплектующими через админ-панель;
- управление готовыми сборками и их составом через админ-панель;
- управление изображениями готовых сборок;
- правила совместимости комплектующих и их CRUD в админке;
- базовый конфигуратор ПК;
- сохранение результата конфигуратора в заявке;
- приём заявок с сайта;
- корректная отправка заявки, если назначение не выбрано (`Не важно`);
- тестовый набор комплектующих для разных конфигураций.

В базе данных уже предусмотрены модели для пользователей и ролей, клиентов, заявок, заказов, оплат, услуг, портфолио, отзывов, статей, SEO и настроек сайта. Часть этих разделов пока является фундаментом для следующих этапов разработки.

## Стек

- **Frontend:** Next.js (App Router) + React + TypeScript + Tailwind CSS
- **Backend:** NestJS + TypeScript
- **База данных:** PostgreSQL
- **ORM:** Prisma

## Установка с нуля

### 1. Клонировать репозиторий

```bash
git clone https://github.com/almaz132423/custompc.git
cd custompc
```

### 2. Поднять базу данных

Из корня проекта:

```bash
docker compose up -d
```

Запускаются:

- **PostgreSQL** — порт `5432`;
- **Adminer** — `http://localhost:8080`.

Проверить контейнеры:

```bash
docker ps
```

Docker Desktop должен быть запущен до выполнения команды.

### 3. Настроить и запустить backend

```bash
cd backend
npm install
```

Создай `backend/.env`:

```env
DATABASE_URL="postgresql://customps:customps_dev_password@localhost:5432/customps?schema=public"
JWT_SECRET="change_this_to_a_long_random_string"
JWT_EXPIRES_IN="7d"
PORT=3001
FRONTEND_URL="http://localhost:3000"
```

Применить миграции:

```bash
npx prisma migrate dev
```

Заполнить БД тестовыми данными:

```bash
npx prisma db seed
```

Seed использует `upsert`, поэтому его можно повторно запускать для обновления тестовых данных без обычного неконтролируемого дублирования.

Запустить backend:

```bash
npm run start:dev
```

Backend: **http://localhost:3001**.

### 4. Настроить и запустить frontend

В новом терминале:

```bash
cd frontend
npm install
```

Создай `frontend/.env.local`:

```env
NEXT_PUBLIC_API_URL=http://localhost:3001
```

Запустить frontend:

```bash
npm run dev
```

Frontend: **http://localhost:3000**.

## Ключевая логика

### Готовые сборки

`PCBuild` хранит готовую конфигурацию ПК, а `PCBuildComponent` связывает её с комплектующими. Для сборок предусмотрены изображения, категория, назначение, разрешение, цена, гарантия и статус.

### Комплектующие

Комплектующие (`Component`) разделены по категориям: CPU, GPU, MOTHERBOARD, RAM, SSD, PSU, CASE и COOLING. Для комплектующих хранятся цена, характеристики (`specs`) и данные совместимости (`compatibility`).

### Совместимость

`CompatibilityRule` хранит активные правила проверки совместимости в JSON. Данные совместимости комплектующих используются движком проверки при формировании конфигурации.

### Конфигуратор

Конфигуратор учитывает назначение, бюджет, разрешение и приоритет, после чего формирует конфигурацию из комплектующих. Результат может передаваться в заявку как снапшот конфигурации.

### Заявки

`Lead` может содержать клиента, бюджет, назначение, категорию обращения, выбранную готовую сборку, комментарий и снапшот конфигуратора. Поле `purpose` необязательное: если пользователь выбирает `Не важно`, поле не отправляется как пустая строка.

## Модель данных

Основные группы моделей Prisma:

- **Авторизация:** `User`, `Role`;
- **Каталог:** `Category`, `PCBuild`, `PCBuildImage`;
- **Комплектующие:** `ComponentCategory`, `Component`, `PCBuildComponent`;
- **Конфигуратор:** `Game`, `ConfiguratorRule`;
- **Совместимость:** `CompatibilityRule`;
- **Заявки и продажи:** `Customer`, `Lead`, `Order`, `OrderItem`, `Payment`;
- **Услуги и контент:** `Service`, `Portfolio`, `Review`, `Article`;
- **SEO и настройки:** `SeoMetadata`, `SiteSettings`.

## API

Основные публичные операции backend:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/pc-builds` | Список готовых сборок |
| GET | `/pc-builds/:slug` | Карточка готовой сборки |
| POST | `/leads` | Отправка заявки |
| GET | `/leads` | Получение заявок для административной части |

Кроме публичных операций, backend содержит защищённые административные операции для комплектующих, готовых сборок, состава сборок и правил совместимости. Для административных операций используется JWT-аутентификация.

## Работа с Git

Рабочий процесс проекта:

1. актуализировать `main`;
2. создать отдельную ветку под задачу;
3. реализовать изменение;
4. проверить изменённые файлы и логику;
5. открыть Pull Request в `main`;
6. после проверки выполнить **Squash and merge**;
7. синхронизировать локальный `main`.

Не следует выполнять разработку непосредственно в `main`, если задача предполагает изменение кода.

## Частые проблемы

**`EADDRINUSE: address already in use`** — порт уже занят другим процессом. На Windows:

```bash
netstat -ano | findstr :3001
taskkill /PID <номер_процесса> /F
```

**Ошибка подключения Prisma к БД** — проверь Docker Desktop и контейнер PostgreSQL:

```bash
docker ps
```

**CORS-ошибка** — проверь `FRONTEND_URL`, `NEXT_PUBLIC_API_URL` и настройки CORS в backend.

**Заявка с `Не важно` не отправляется** — убедись, что frontend отправляет отсутствие `purpose`, а не пустую строку `purpose: ""`.
